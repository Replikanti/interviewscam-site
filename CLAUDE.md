# CLAUDE.md: interviewscam

Community registry of fake job-interview scams that target developers, built as a static Hugo site for interviewscam.com. The repo is private and the site is public, so everything that builds into the site is public content.

## Source of truth

- [docs/SPEC.md](docs/SPEC.md) is the source of truth. Anything not written there is not agreed. A scope change is a PR that edits the SPEC.
- A change to a SPEC §4 decision (D1 to D10) also adds an ADR in [docs/adr/](docs/adr/README.md). Every ADR decision states why and which alternatives lost, and every number states where it comes from and what breaks at another value. A number copied from another ADR needs its own reason.

## Local check

One entry point, and CI runs it verbatim:

```sh
bash tools/check.sh             # internal links offline
bash tools/check.sh --external  # links online, third-party sources included
bash tools/selftest.sh          # the fixtures alone (check.sh runs it too)
```

Prerequisites: bash, python3 3.11 or newer, curl, sha256sum, tar and shellcheck. No container runtime and no browser. `tools/fetch-tools.sh` downloads Hugo and lychee into `.tools/` and verifies each against the SHA-256 in `tools/pins.env` before extracting.

**HTML validation and reflow run only in CI** ([ADR-0002](docs/adr/0002-check-toolchain.md) part 1, [ADR-0003](docs/adr/0003-browser-checks.md) part 6). Locally the Nu Html Checker step and the reflow step each print a `NOT RUN` line, and the final line reads `LOCAL PASS, HTML validation and reflow not run (CI only)`. A local green means neither that the HTML is valid nor that the pages reflow at 320 CSS px; the SPEC §8 HTML row and the reflow part of the accessibility row come only from the `check` job in CI. In CI a missing Docker image or Google Chrome is FAIL. The reflow check never looks for a browser outside `PATH` (for example a flatpak).

Steps, in order: fetch and verify the toolchain, shellcheck `tools/*.sh` (prints `shellcheck OK`; required under `CI=true`), `sitecheck guard`, `sitecheck records`, `sitecheck tokens`, the Hugo build into `public/` with `--panicOnWarning`, `sitecheck site` on `public/`, `sitecheck reflow` on `public/` (CI only), the Nu Html Checker (CI only), lychee on `public/`, and the self-test. Every step runs even after a failure, and the summary lists each result.

Self-test: every `tests/fixtures/<check>/<pass|fail>-<case>/` runs through the same function as the real step. A `pass-` case must exit 0, and when it has an `expect.txt` its output must contain that substring too (so a pass that checked nothing, for example zero records, is caught). A `fail-` case must exit non-zero and print the substring in its `expect.txt`. Fixture directories: `html`, `links`, `records` (against the real `schema/`), `schema` (each case brings its own `schema/`), `site` (`hugo.toml` with `params.csp`, `content/` records, the built tree in `public/`), `tokens` (the case stands in for the repo root: `data/tokens.toml` plus the `assets/`, `layouts/`, `static/` and `hugo.toml` the colour scan reads), `reflow` (the case is the built tree itself; CI only, counted like the html fixtures: `reflow fixtures run: N of M`, and in CI the self-test fails unless all ran), `guard` (the case stands in for the repo root; an optional `env.txt` holds `HUGO_*` overrides for the run), `lighthouse` (synthetic report JSON with only the fields the score gate reads, checked against the fixed version `LIGHTHOUSE_FIXTURE_VERSION` in `selftest.sh`, not the pin) and `tree` (a resolved tree in `lock.json`, because the guard rejects the real lockfile name, and the digest the case pins in `pin.txt`).

## Safety nets (`tools/sitecheck.py`)

Python 3.11+ standard library, one file, always run as `python3 -I` ([ADR-0002](docs/adr/0002-check-toolchain.md) parts 3 and 4). Exit 0 clean, 1 on findings, 2 on a usage or internal error. A finding never prints an artifact live: values are shown defanged.

- `records`: every `content/reports/*.md` and `content/campaigns/*.md` except `_index.md` is a record with TOML front matter between `+++` lines, validated against `schema/report.schema.json` or `schema/campaign.schema.json` (M1 placeholders, M3 replaces them). Any other directory under `content/`, a nested file or YAML front matter fails closed. The validator implements `type`, `required`, `properties`, `additionalProperties`, `items`, `enum`, `const`, `pattern`, `minLength`, `minItems`, `format: date`, annotations and `x-defang`; any other keyword is an error. `x-defang: "host"` rejects a live scheme anywhere, and a `www.` prefix, a live hostname (dot look-alikes included) or a live dotted IPv4 in the host part of each token (after `scheme://`, `//` or `\\`, before the first `/`, `?`, `#` or `\`), so a dot in a defanged URL's path or query (`/GoogleMeet.exe`, `?id=abc.def`) is not a hostname; `x-defang: "url-only"` rejects only the live scheme (package names with dots). The live form of an artifact (`[.]`, `hxxp`, `[:]`, `[@]` refanged) must not appear in any other string or body of any record (R2). Bodies carry no bare URLs (any scheme except `hxxp`/`hxxps`, `//host`, `www.`, `mailto:`), no `hxxp(s)://` with a live host after it, no live dotted IPv4, no Markdown links, images, reference links or definitions (a definition label may span lines or hold `\]`), no `<…>` autolinks and no Hugo shortcodes (`{{<`, `{{%`: their output, for example `param` or `figure link=`, is invisible to this check), also not after entity or backslash decoding (SPEC §5). The rule fails closed: links in code spans count too, and even a defanged URL in an autolink is a link. Every front-matter string outside `params.sources` that is not an artifact field gets the URL rules too (bare URL, half-defanged URL, `//host`): live links live only in `params.sources`.
- `site`: on every HTML page under `public/`, no URL to another origin or scheme (after stripping C0 controls and spaces, as the WHATWG URL parser does) in the attributes that make the browser fetch (`script`, every `link`, `img`/`source` incl. `srcset`, media, frames, `embed`, `object`, `a[ping]`, SVG `image`/`use`, `meta` refresh, any `<base>`, `background`), nor in CSS (`url()`, `@import`, quoted strings, escapes decoded, comments stripped without touching strings), `.js` URL literals, or any attribute, `<?xml-stylesheet?>` or declaration of an `.svg`, `.xml`, `.xsl`, `.xslt`, `.rss` or `.atom` file (no CSP applies to those). `<a href>` is allowed: a click is a navigation. Exactly one CSP meta per page, the first element after `<meta charset>`, equal to `params.csp`; the policy may only use `'self'` and `'none'` and must set `default-src`. The live form of any record artifact appears nowhere in `public/`: raw, entity-decoded, percent-decoded, as joined page text, and as every string of every `.json` file (the stand-in for M3's `/feed.json`). Markup rules on every HTML page (attribute values entity-decoded, URL schemes read as a browser reads them, case-insensitive): (a) no `<form action>`, `<button formaction>` or `<input formaction>` to another origin or scheme; (b) no `.webmanifest` file and no `<link rel~="manifest">` (fail closed until a manifest's `icons[].src` are request-scanned); (c) no `style` attribute, no `<style>` element, no `<script>` without `src` except `type="application/ld+json"` data blocks, no `on*` attribute and no `javascript:` URL in `href`, `src`, `action`, `formaction`, `xlink:href` or `data`, because the CSP blocks all of them silently; (d) every page except the root `404.html` has exactly one `<link rel="canonical">`, equal to `https://interviewscam.com` plus its own path (`index.html` maps to its directory), and `404.html` has none ([ADR-0003](docs/adr/0003-browser-checks.md) part 3); (e) no `mailto:` URL in `href`, `action`, `formaction` or `xlink:href` (SPEC §7: the address is plain text); (f) colours of the built site: in every built `.css` file no backslash escape outside a string, and in every declaration value, every colour attribute (`fill`, `stroke`, `color`, `stop-color`, `flood-color`, `lighting-color`), the `theme-color` meta, `style` attributes and `<style>` blocks of HTML, SVG and XML files, a hex colour must equal a colour of `data/tokens.toml` (3- and 4-digit forms expanded, because the minifier shortens them; no tokens file means no hex passes), and no colour function, no named or system colour and no vendor-prefixed value (`-webkit-`, `-moz-`, `-ms-`, `-o-`: `-webkit-link` is a colour) may appear; prefixed property names stay allowed; the presentational attributes `bgcolor`, `text`, `link`, `alink` and `vlink` fail outright. This sees what templates inject from `data/`, `hugo.toml` or front matter, which the source scan of `tokens` cannot. (h) no `<textarea wrap="off">` (its text could not wrap). (g) no SMIL animation element (`set`, `animate`, `animateTransform`, `animateMotion`, `animateColor`) in any built HTML, SVG or XML file: it can set an `href` (`mailto:`, `javascript:`) or a colour at run time. In the built CSS ([ADR-0003](docs/adr/0003-browser-checks.md) part 6), counted across ALL files, not per file: exactly one top-level `.visually-hidden` rule when a page uses the class (at most one otherwise), with `display: block`, `position: absolute`, `width: 1px`, `height: 1px`, `overflow: hidden`, `clip-path: inset(50%)` and `white-space: nowrap`, each exactly once (`display: block` keeps out `display: contents`), plus only `margin`, `padding`, `border` and `clip`; at most one top-level reveal whose selectors are `.visually-hidden:focus` and/or `.visually-hidden:focus-visible`; every declaration of both is `!important`; the class appears in no other selector (compound, descendant, other pseudo-class), in no rule nested in an at-rule (`@media`, `@container`, `@supports` and any other) and in no declaration; no attribute selector on `class` at all (it could match the class without naming it); `!important` appears nowhere else. Comments are stripped and CSS escapes decoded first (`!\69mportant` counts).
- `guard`: no JavaScript package-manager files in the tracked or untracked (not ignored) files, and no tool names from its pattern table in `tools/`, `.github/workflows/`, `.github/actions/` or any script elsewhere (by suffix, make/just file name or `#!` line; site sources under `assets/`, `layouts/`, `static/`, `content/`, `data/`, `i18n/`, `archetypes/`, plus `docs/` and `tests/fixtures/` are not executed and not scanned). Write comments there without those names; only the table lines in `sitecheck.py` are skipped, and the guard's own `tests/fixtures/guard/fail-*` cases, which the self-test proves, are skipped for the file rule. A workflow `run:` may only be `bash tools/<name>.sh` with plain `--flags` (no inline scripts or block scalars), `shell:` only `bash`, and no `container:`, `services:`, `entrypoint:`, `working-directory:`, `env:` or `defaults:` (a working directory or `BASH_ENV` can point a run step at unscanned code), so everything a workflow executes is a scanned `tools/` script. YAML forms the per-line rules cannot read fail closed: a `pages:`/`id-token:` value on the next line or behind an anchor, alias, tag or block scalar, any double-quoted string with a `\` escape anywhere on the line (block or flow style), a `? ` complex key. The Hugo hardening keys are asserted in `hugo.toml` AND in the effective config from `"$HUGO_BIN" config --format json`, which sees `config/` directories, `HUGO_*` environment variables and case-variant keys; `params.csp` must match too. A `config/` directory or a second root config file (`hugo.*`, `config.*`) fails. The effective config must keep `contentdir = "content"`, no `theme`, no `module.imports`, and every content mount `content` to `content`, because the records check reads only `content/`. Every `uses:` is `actions/<name>@<40-hex SHA>` AND equals one of the `ACTION_*` pins in `tools/pins.env` (a commit that exists only in a fork resolves under `actions/` too). Every workflow has a top-level `permissions:` block, and none contains `deploy-pages`, `configure-pages`, `pages: write`, `id-token: write` or `write-all` (Pages off until M6, which removes that rule deliberately). The Lighthouse carve-out ([ADR-0003](docs/adr/0003-browser-checks.md) part 2): `tools/lighthouse.sh` is the only file the tool-name scan skips, and no scanned file except `tools/lighthouse.sh`, `tools/sitecheck.py` and `.github/workflows/lighthouse.yml` may contain `lighthouse.sh`, so `check.sh`, `selftest.sh`, `fetch-tools.sh` and the other workflows (the deploy job among them) can never reach it. In `lighthouse.yml`, every job that runs it has exactly one job-level `permissions: {}` and no `actions/checkout`, and the file never names the Pages artifact (`upload-pages-artifact`, `github-pages`). Jobs are read by indentation under `jobs:`, so any anchor, alias or flow mapping in that file except `permissions: {}` fails closed. Nothing that holds a token, and nothing on the deploy path, reads what that job could write: `actions/download-artifact` appears only in the job `lighthouse` of `lighthouse.yml`, no workflow uses a `workflow_run` trigger, no job `needs:` the job that runs `lighthouse.sh` (it stays a leaf), and that job uses no `upload-artifact` or `upload-pages-artifact`. No credential reaches it: any `secrets` or `github.token` reference, and any `github-token:`, `run-id:` or `repository:` input, anywhere in `lighthouse.yml` (comments included) fails.
- `tokens [--root <dir>]` (SPEC §7): `data/tokens.toml` parses; its top-level keys are `color`, `pair`, `font` and the number tables `weight`, `type`, `line_height`, `space`, `layout`, `radius`, `target`, `focus`, `border`, `shadow`, `underline` (any other key fails closed); keys are snake_case; colours are `#RRGGBB` or `#RRGGBBAA`; numbers are positive; fonts are non-empty strings. Every `[[pair]]` has exactly `fg`, `bg`, `kind`, `ratio` and `use`; `fg` and `bg` name opaque colours; `(fg, bg, kind)` is unique; `kind` is `text` (4.5:1), `large_text` (3:1) or `non_text` (3:1); `ratio` equals the WCAG 2.2 ratio floored to 2 decimals, and the ratio meets the minimum. It prints the contrast of every pair. The colour-literal scan reads every file under `assets/`, `layouts/` and `static/` plus `hugo.toml`, template actions included: hex colours (`#` plus 3, 4, 6 or 8 hex digits, not followed by a word character, not an `&#123;` entity; a fragment id that looks like hex fails closed, so rename it) and colour functions (`rgb`, `rgba`, `hsl`, `hsla`, `hwb`, `lab`, `lch`, `oklab`, `oklch`, `color`, `color-mix`, `light-dark`, `contrast-color`, `device-cmyk`). In `.css` sources it also bans backslash escapes outside strings. In `.css` declarations (escapes decoded) and in the `style`, `fill`, `stroke`, `color`, `stop-color`, `flood-color` and `lighting-color` attributes and the `theme-color` meta of `.html`, `.svg` and `.xml` sources, it also rejects colour functions, vendor-prefixed values and the CSS named and system colours, and the presentational attributes `bgcolor`, `text`, `link`, `alink`, `vlink` and SMIL animation elements fail (`currentcolor`, `transparent` and the CSS-wide keywords are allowed; the deprecated system colour `background` is not listed, because it is also a `transition` property name). Raster images are skipped; any other file that is not UTF-8 fails closed. `content/` and `data/` are not scanned: Markdown cannot carry styles (`unsafe = false`), and copy may contain "#123". The source scan is early feedback with line numbers; the binding colour check is `site` rule (f) on the built site. Where a pair is placed is not provable here: Lighthouse's contrast audit covers rendered text, review covers non-text placement (`input_border` only on `card`).
- `reflow --chrome <bin> <public>` ([ADR-0003](docs/adr/0003-browser-checks.md) part 6, CI only, standard library only): serves `<public>` on `127.0.0.1`, starts the runner's Google Chrome headless with `--remote-debugging-pipe` (the DevTools protocol on file descriptors 3 and 4; no websocket, no registry code), emulates a 320×640 mobile viewport, loads every `.html` file and checks geometry, not CSS properties: (1) page-level overflow, `document.documentElement.scrollWidth` above 320, naming the innermost elements that stick out; (2) every word of text (one DOM range per run of non-space characters) and the box of every replaced element (`img`, outermost `svg`, `video`, `audio`, `iframe`, `canvas`, `object`, `embed`, `input`, `select`, `textarea`, `meter`, `progress`) lies horizontally within [0, 320]; (3) and within the box of every clipping ancestor (computed `overflow-x` not `visible`, `contain` with paint, `content-visibility` not `visible`: padding box; `clip-path` or `clip`: border box); (4) an element with the class `visually-hidden` has a box of at most 1 × 1 px and a computed `display` other than `contents`, and only then are it and its subtree exempt; (5) no `input`, `textarea` or `select` has a `scrollWidth` above its `clientWidth` (their text has no DOM range). Tolerance 0.5 px. A 4xx/5xx answer of the local server (except `/favicon.ico`, which Chrome requests on its own) fails too, because the page was then measured without one of its files. Chrome or protocol errors are exit 2. Not measured: vertical clipping, `display`/`visibility`/`opacity` hiding, overlap, a `clip-path` or `mask-image` shape smaller than its box, CSS-generated text, and other widths than 320 px (ADR-0003 part 6, weak points).
- `lighthouse --reports <dir> --version <v>`: the score gate ([ADR-0003](docs/adr/0003-browser-checks.md) part 3) on Lighthouse JSON reports. Exactly 3 reports per page (grouped by `requestedUrl`), no `runtimeError`, `lighthouseVersion` equal to the pin, `formFactor` `mobile`, every category present with a numeric score, the audited URL on loopback `http`, and every `network-requests` item on the audited origin (a runtime D9 check; a missing audit fails closed). The median per category must be at least `LIGHTHOUSE_MIN_SCORE` (95, SPEC §8), a constant and not a flag. It prints the page × category median table, the failing weighted audits of the median run for a category under the threshold, a `note:` line for a category between 95 and 99, and one `canonical audit on <page>:` line with that audit's score in every run (shown, not gated; it weighs into SEO), so a run log shows the canonical audit on the real tags (ADR-0003 part 3).
- `tree-digest <lockfile> --expect <sha256>`: the resolved dependency tree ([ADR-0003](docs/adr/0003-browser-checks.md) part 1). Lockfile versions 2 and 3 only. Every entry needs a `version`, a single `sha512-` integrity and a `resolved` URL on the public registry; link entries and keys outside the install-directory layout fail closed. The name is the key's last path segment (the last two for a scope), so the code names no tool. The SHA-256 of the sorted, unique `name@version integrity` lines must equal `--expect`; on a mismatch it prints the digest and the `name@version` list for review.

## Invariants

- **No npm (D3).** Never run `npm`, `npx` or `node` on a developer machine, not even for a quick Lighthouse run. No `package.json` or lockfile in the repo. The `[security]` and `[privacy]` keys in `hugo.toml` stay (ADR-0001 hardening keys). npm-only tools run only in CI jobs whose `GITHUB_TOKEN` has no permissions (`permissions: {}`), that see only the built site and the check scripts, never the repository source, and that do not build the deploy artifact. Today that is the job `lighthouse` in `lighthouse.yml`, running `tools/lighthouse.sh`, the only file that may name the tools ([ADR-0003](docs/adr/0003-browser-checks.md) part 2). That script refuses to run outside GitHub Actions or next to `.git` or `content/`. No workflow restores an Actions cache, and the deploy path never reads anything that job can write.
- **Neutral, artifact-based records (D6, D7, D10).** A record describes artifacts, not a verdict about a company. A company or person name is either "name abused" (used without their involvement) or "front" (listing what was checked). Labels state facts, for example "reported 3 times, evidence reviewed on 2026-11-10", never "verified scam". A recruiter persona name appears only with the label "name used by the campaign, possibly a stolen identity". Attribution only as the cited source states it.
- **Nothing live (D8).** Attacker URLs and domains are always defanged: `hxxp://` or `hxxps://`, and every dot in a hostname or IP as `[.]`, for example `hxxps://login[.]meeting[.]example/join`. This applies to records, page copy, issues, PR bodies and QA reports. Record bodies carry no bare URLs, no Markdown links and no `<…>` autolinks; live links appear only in `sources`. No malware binaries, only SHA-256 hashes linking to MalwareBazaar or VirusTotal; never download a sample to check a hash. Fixtures use only RFC 2606 reserved names (`.example`, `.test`, `.invalid`, `example.com`).
- **No third-party requests (D9).** No external scripts, stylesheets, fonts, analytics or cookies. The Content Security Policy is a meta tag right after `<meta charset>` (Pages cannot set headers), and its single source is `params.csp` in `hugo.toml`.
- **Pages stays off until M6 (#7).** On the Team plan a Pages site from this private repo is public as soon as it deploys. `deploy.yml` only builds and uploads the artifact with a read-only token; no workflow may deploy or enable Pages before M6.
- **No raw evidence or personal data** in the repo, issues or PRs: no reporter identity, unredacted screenshots or mail headers. They stay in the operator's mailbox (D5, D7). Issues carry only defanged artifacts and an evidence summary.

## Load-bearing names

- The CI job `check` in `.github/workflows/ci.yml`. Branch protection requires exactly this context, so a rename must update the protection in the same session.
- The schema keyword `x-defang` and its modes `host` and `url-only`, which mark the record fields that carry attacker artifacts ([ADR-0002](docs/adr/0002-check-toolchain.md) part 4).
- `tools/lighthouse.sh`, the workflow file `.github/workflows/lighthouse.yml` and its jobs `build` and `lighthouse`: the guard's carve-out names them ([ADR-0003](docs/adr/0003-browser-checks.md) part 2). `lighthouse` is not a required check, but an agent session never merges a PR whose `lighthouse` run is red or pending (ADR-0003 part 4).
- `RECORD_SCHEMAS` in `tools/sitecheck.py`, which maps `content/<section>/` to its schema. A new record section needs an entry, or the records check fails closed.

## Workflows

- `ci.yml`: job `check`, on every PR and every push to `main`, runs `bash tools/check.sh`.
- `deploy.yml`: job `pages-artifact`, on pushes to `main` and on PRs that change it, runs `bash tools/check.sh` and uploads `public/` as the Pages artifact. It does not deploy.
- `links-external.yml`: weekly and on manual start, runs `bash tools/check.sh --external`. Not a required check.
- `lighthouse.yml` ([ADR-0003](docs/adr/0003-browser-checks.md)): on PRs that touch the site-shaping paths (`layouts/`, `assets/`, `static/`, `data/`, `i18n/`, `archetypes/`, `content/*.md`, `hugo.toml`, `tools/`, the workflow itself), on every push to `main` and on manual start. Job `build` (`contents: read`) runs `bash tools/check.sh` and uploads `public/` and `tools/` as the artifact `built-site` (1 day). Job `lighthouse` (`needs: build`, `permissions: {}`, no checkout) downloads that artifact and runs `bash tools/lighthouse.sh`, which uploads nothing. Not a required check.

Every action is owned by `actions/`, pinned to a 40-hex commit SHA with the tag as a comment, and listed as an `ACTION_*` pin in `tools/pins.env`. Runners are `ubuntu-24.04`, not `ubuntu-latest` (ADR-0002 part 5). Tokens are read-only.

## Upgrading a tool

Hugo: the pinning procedure in [ADR-0001](docs/adr/0001-static-site-generator.md). lychee and the Nu Html Checker image: [ADR-0002](docs/adr/0002-check-toolchain.md) parts 1 and 2, including the fallback when the pinned image digest disappears upstream. Actions: resolve the upstream tag ref (`GET /repos/actions/<name>/git/ref/tags/<tag>`), then change the `ACTION_*` pin in `tools/pins.env` and the `uses:` line together. Every pin changes only in its own PR, which runs the full check.

Upgrading Lighthouse ([ADR-0003](docs/adr/0003-browser-checks.md) part 1 and Consequences): in one PR, bump `LIGHTHOUSE_VERSION` and set `LIGHTHOUSE_BEFORE` to the pin date minus 7 days (the version must be published before it). The `lighthouse` job then fails at the digest step and prints the new digest and the resolved `name@version` list. Check that list against the expected set of packages (names and versions, not code), copy the digest into `LIGHTHOUSE_TREE_SHA256`, and push; the run must go green. Never resolve or install the tree locally (D3). A runner image whose resolver changes the tree fails the same way and is re-pinned the same way.

## Content scrub

Before every commit, the staged diff (`git diff --cached`) must contain no client names and no paths from a developer machine (home directories, worktree paths). Envelope SDLC sessions run the scrub grep from their repo routing table. The pattern is not written here, because a file that spells out the names would itself match the scrub.
