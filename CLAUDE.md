# CLAUDE.md: interviewscam

Community registry of fake job-interview scams that target developers, built as a static Hugo site for interviewscam.com. The repo is private and the site is public, so everything that builds into the site is public content.

## Source of truth

- [docs/SPEC.md](docs/SPEC.md) is the source of truth. Anything not written there is not agreed. A scope change is a PR that edits the SPEC.
- A change to a SPEC §4 decision (D1 to D10) also adds an ADR in [docs/adr/](docs/adr/README.md). Every ADR decision states why and which alternatives lost, and every number states where it comes from and what breaks at another value. A number copied from another ADR needs its own reason.

## Local check

One entry point, and CI runs it verbatim:

```sh
bash tools/check.sh             # internal links offline
bash tools/check.sh --external  # links online, third-party sources included (the fixture build stays offline)
bash tools/selftest.sh          # the fixtures alone (check.sh runs it too)
```

Prerequisites: bash, python3 3.11 or newer, curl, sha256sum, cmp, tar and shellcheck. No container runtime and no browser. `tools/fetch-tools.sh` downloads Hugo and lychee into `.tools/` and verifies each against the SHA-256 in `tools/pins.env` before extracting.

**HTML validation and reflow run only in CI** ([ADR-0002](docs/adr/0002-check-toolchain.md) part 1, [ADR-0003](docs/adr/0003-browser-checks.md) part 6). Locally the Nu Html Checker step and the reflow step each print a `NOT RUN` line (the reflow one also names its hidden-state cases, the Copy button hidden without its script, the search results hidden until a query (M4 PR 3) and the skip link shown on keyboard focus, M3 PR 10), and the final line reads `LOCAL PASS, HTML validation and reflow not run (CI only)`; from M4 PR 4 the reflow line also names the hit test and paint check of the pinned regions and case (8), the search typed and submitted on Home. A local green means neither that the HTML is valid nor that the pages reflow at 320 CSS px; the SPEC §8 HTML row and the reflow part of the accessibility row come only from the `check` job in CI. In CI a missing Docker image or Google Chrome is FAIL. The reflow check never looks for a browser outside `PATH` (for example a flatpak).

Steps, in order: fetch and verify the toolchain, shellcheck `tools/*.sh` (prints `shellcheck OK`; required under `CI=true`), `sitecheck guard`, `sitecheck records`, `sitecheck tokens`, `sitecheck literals`, the Hugo build into `public/` with `--panicOnWarning`, `sitecheck site` on `public/`, `sitecheck render` on `public/` (with the fixture-leak check and the feed rules), the fixture build into `public-fixtures/` (after classifying its inputs), `sitecheck site` and `sitecheck render` on `public-fixtures/` (no fixture-leak check: every record there is a fixture), `sitecheck reflow` on both trees (CI only), the Nu Html Checker on both trees (CI only), lychee on `public/` (online with `--external`), lychee on `public-fixtures/` (always offline: fixture sources and lookups are placeholders), and the self-test. Every step runs even after a failure, and the summary lists each result.

Fixture build ([ADR-0004](docs/adr/0004-record-model.md) part 10): production `content/` has no records until milestone 5, so the record templates would meet no check before then. `step_fixture_build` in `tools/check.sh` removes `.fixture-site/` and `public-fixtures/`, classifies the inputs (`fixture_inputs`, below), copies the `FIXTURE_COPY` entries that exist (`hugo.toml`, `layouts/`, `assets/`, `data/`, `static/`, `i18n/`, `archetypes/`) and the top-level `*.md` of `FIXTURE_CONTENT` (`content/`) into `.fixture-site/`, adds `tests/fixtures/records/pass-fixture-site/content/`, and builds it with the same Hugo invocation as the production build (`hugo_build`) into `public-fixtures/`. Both directories are git-ignored, the fixture records never enter `content/` (`render`'s fixture-leak check on `public/`), and the deploy artifact stays `public/` alone. A change to a record template is therefore checked by `render (fixture build)`, reflow and the HTML checker on the fixture pages, and Lighthouse on the six fixture pages of `LH_FIXTURE_PAGES`. Classified inputs (ADR-0004 part 10, amended): Hugo reads the disk, not git, so `fixture_inputs "$CHECK_ROOT"` lists every top-level entry of the root on disk, dot entries included, and fails before the build on an entry in none of `FIXTURE_COPY`, `FIXTURE_CONTENT` and `FIXTURE_SKIP` (`unclassified top-level path '<name>'`) or a name in two (`classified twice`), and on an entry of `content/` that is neither a `*.md` file nor a record section of `FIXTURE_RECORD_SECTIONS` (`reports`, `campaigns`: `unclassified content entry 'content/<name>'`), because the fixture build would silently lack it. A new top-level file or directory goes into one array in the same PR; an untracked one on a developer machine fails a local run until it is removed or classified.

## Safety nets (`tools/sitecheck.py`)

Python 3.11+ standard library, one file, always run as `python3 -I` ([ADR-0002](docs/adr/0002-check-toolchain.md) parts 3 and 4). Exit 0 clean, 1 on findings, 2 on a usage or internal error. A finding never prints an artifact live: values are shown defanged. Every Default_Ignorable_Code_Point (`INVISIBLE`, ranges copied from Unicode's DerivedCoreProperties.txt) is stripped before the record checks, because browsers drop them from hosts; emoji in prose keep passing. The live-form fold `norm()` applies NFC after the strip (M4 PR 4 fix round 1), so a stripped character between a letter and its accent leaves the two to compose (fixtures `site/fail-live-artifact-composed-after-invisible`, which only that NFC catches, and `records/fail-live-form-composed-after-invisible`).

- `records`: every `content/reports/*.md` and `content/campaigns/*.md` except `_index.md` is a record with TOML front matter between `+++` lines, validated against `schema/report.schema.json` or `schema/campaign.schema.json` (the SPEC §5 model, [ADR-0004](docs/adr/0004-record-model.md)). The schemas describe structure only, with `additionalProperties: false` at every level and a `description` on every property; the only top-level keys are `date` (the publication date) and `params`, so a record cannot set `title`, `url`, `slug`, `aliases`, `draft`, `build`, `outputs`, `layout`, `type`, `cascade`, `publishDate` or `expiryDate`. Validity lives in two places, the schema and the record rules below (ADR-0004 part 2). Any other directory under `content/`, a nested file or YAML front matter fails closed. The validator implements `type`, `required`, `properties`, `additionalProperties`, `items`, `enum`, `const`, `pattern`, `minLength`, `minItems`, `minimum` (numbers only), `format: date`, annotations and `x-defang`; any other keyword is an error. `x-defang: "host"` is the only mode and marks every artifact field plus the record names and aliases (`packages[].name` and `handles[].value` included, so a dotted package name is stored `socket[.]io`); the former mode `url-only` fails closed. It scans the whole value in every reading (as written, with `[://]`, `[:]` and `[@]` read as `://`, `:` and `@` through the `DEFANGS` table that `refang()` also uses, and percent-decoded) and rejects a live scheme, a `www.` prefix, a live dotted name (dot look-alikes included) and a live dotted IPv4 anywhere, a path, query, file name or repository shorthand included: write `hxxps://get[.]meeting[.]example/GoogleMeet[.]exe` and `attacker/interview[.]task`. No host has to be found first, so no scheme spelling can hide one (ADR-0004 amendment). A `urls` value must take the form `hxxp` or `hxxps`, then `://`, `[://]` or `[:]//`, then a non-empty authority that is not a bracketed IPv6 literal, then an optional path, query or fragment (`URL_FORM`); anything else is a format finding. In every host-mode field an IPv6 literal, bracketed or bare, is a finding (an IPv6 artifact cannot be declared): candidates are bracket contents and standalone colon runs, and only one that parses with `ipaddress` counts, so `dead:beef` or `Fixture::Utils` pass, and R12 reads a URL's host only from that authority. In the other fields R12 reads the host part of every token. A bare single decimal or octal number (no dot, no `0x`, not after a scheme) is an integer IPv4 when it is the whole value or the whole first part of it (`3232235777`, `2130706433/setup`), except in `handles[].value`, where it is a numeric handle; a number inside a longer value ("Studio 54") is not a host. The live form of an artifact (`[.]`, `hxxp`, `[:]`, `[@]` refanged) must not appear in any other string or body of any record (R2). Bodies carry no bare URLs (any scheme except `hxxp`/`hxxps`, `//host`, `www.`, `mailto:`), no `hxxp(s)://` with a live host after it, no live dotted IPv4, no Markdown links, images, reference links or definitions (a definition label may span lines or hold `\]`), no `<…>` autolinks and no Hugo shortcodes (`{{<`, `{{%`: their output, for example `param` or `figure link=`, is invisible to this check), also not after entity or backslash decoding (SPEC §5). The rule fails closed: links in code spans count too, and even a defanged URL in an autolink is a link. Every front-matter string except `params.sources[].url` that is not an artifact field gets the URL rules too (bare URL, half-defanged URL, `//host`): the only live links are `params.sources[].url`. Then the record rules of ADR-0004 (its table "Record rules R4 to R15" is the definition; each rule reads only values of the right type, so a missing field is the schema's finding alone, and each has a fail fixture under `tests/fixtures/records/` or, when it needs its own policy file, `tests/fixtures/schema/`):
  - R4, slugs: a report or campaign slug (the file name) is `slugify(params.name)` or that plus `-N` with N ≥ 2 (NFKD ASCII folding, lowercase, `[.]` and every non-alphanumeric run as `-`, trimmed); a persona report's slug is `persona-N` with N ≥ 1, so its URL never carries a name; a name that slugifies to nothing fails; no slug appears in `retired_slugs` of `schema/record-policy.json`. That file holds exactly `{"retired_slugs": [...]}`: a missing file, another key (no allowlist, ADR-0004 part 3) or an entry that is not a slug is a finding. A removed slug goes into it in the removal PR and is never reused.
  - R5, persona names: the `params.name` and every alias of a persona record (NFKC, case-folded, whitespace collapsed, whole word, no minimum length, also with inline markup stripped) appear in no front-matter string outside `params.artifacts` and the source URLs, and in no body, of any record (its own name and alias fields excepted), so `hide_name` removes the name in one line.
  - R6: `params.hide_name` only with `name_type = "persona"`.
  - R7, references: `params.campaign.slug` names a campaign record; `params.campaign.source` and every `params.attribution[].source` name a source `id` of the same record, and source ids are unique per record; `params.related` entries name other report records, never the record itself; `basis = "artifact"` needs `params.campaign.artifact`, equal to one of the record's declared artifact values, and `basis = "named"` forbids it. A mistyped value is the schema's finding, never a crash.
  - R8, dates: reports `first_seen ≤ last_seen ≤ last_reviewed`, campaigns `first_seen ≤ last_seen`.
  - R9, evidence: `independent_reports ≥ 1`, or at least one source (a source-only report, ADR-0004 part 12). R10: a report declares at least one artifact.
  - R11, hostnames in record text: record text is every body, every `_index.md` and every front-matter string except the `x-defang` fields and `params.sources[].url` (source titles and publishers are record text). In it, a live dotted name, a live dotted IPv4, a `www.` prefix and an email address on a live host fail unless the folded host is exactly `interviewscam.com` (the host of `SITE_ORIGIN` in `sitecheck.py`, the single source). No other exemption: no allowlist, no exemption for declared artifacts or file extensions. The whole text is read, a URL's path, query and fragment included (`hxxp://x/payload.attacker.example`, `C:\Users\Public\Setup.zip`, `Kaspersky/Dr.Web`), so a defanged URL quoted from an artifact writes its path dots as `[.]` too. The only other copy sources are content and the `hugo.toml` identity facts `title`, `params.operator` and `params.contact` (D1). The D6, D7 and D10 wording, the titles (the persona head form included), the A to Z entry wording (`INDEX_CAMPAIGN_LINE`, `INDEX_ALIASES_LINE`, `NAME_TYPES`, `HIDDEN_NAME`) the no-report block (`NO_REPORT_BROWSE_TEXT`, `NO_REPORT_TEXT`, the two link texts of `NO_REPORT_LINKS`) and the search result sections (`SEARCH_SECTIONS`, `WHAT_TO_DO_*`, `A_Z_LINK_TEXT`) are pinned a second time as constants in `tools/sitecheck.py`, independently, so a copy change needs both and shows up in a safety-net diff (ADR-0004 Consequences).

The fixture records carry unbroken tokens of 64 or more characters in each of these fields, so the CI reflow of the fixture build proves it. The warning panel ("What to do now") is the only orange besides the CTA; its links take `warn_text`, because primary on `warn_bg` is not a listed pair.

## Design (SPEC §7, direction C "Signal")

- **Tokens.** `data/tokens.toml` is the only place a colour value may live. `assets/css/tokens.css` is a template that turns it into custom properties (`--<table>-<key>`, `_` as `-`, for example `--color-chip-text`; lengths as rem, hairlines as px), and `layouts/baseof.html` concatenates it in front of `assets/css/site.css`, minifies and fingerprints the result as the one stylesheet. `site.css` uses `var(--…)` for every colour. `assets/favicon.svg` and the `theme-color` meta read the tokens too. Read the data through `hugo.Data`, never `.Site.Data` (deprecated; the build runs with `--panicOnWarning`).
- **Adding a colour.** Add the key with a comment on why it exists, then a `[[pair]]` for every foreground/background combination the layout places it in, with the floored ratio (`sitecheck tokens` prints the real value when the stated one is wrong). A colour that only decorates (a border the surface change already carries) gets no pair and says so in its comment.
- **Placement.** `input_border` is 3.15:1 on `card` but 2.91:1 on `ground`, so inputs and bordered buttons sit only on cards; review checks it, the check cannot. Orange (`cta`, `warn_*`) only on warnings and the call to action, never on a state chip (D6).
- **Markup.** No `style` attribute, `<style>` element, inline script or `on*` handler (the CSP blocks them; `site` rule (c)). Two pinned scripts ([ADR-0005](docs/adr/0005-search.md) part 5): `assets/js/copy.js` on every page and `assets/js/search.js` on Home only (`eq .Kind "home"`), each loaded once by `baseof.html` (minified, fingerprinted with SHA-384, `integrity`, `defer`; `site` rule (j)). Icons come from `layouts/_partials/icon.html`: inline SVG, `aria-hidden`, stroked in `currentColor`, coloured by a CSS class on the element around them. `visually-hidden` is the one utility class (the skip link) and, with the rules `.copy[hidden]` and `.search-out[hidden]`, the only place for `!important` (ADR-0003 part 6, ADR-0004 part 11, ADR-0005 part 6). The layout is fluid (`flex-wrap`, `min-width: 0`) and reflows at 320 CSS px. The only media queries compact the header below 390 px (24rem and 21.25rem: smaller wordmark, CTA and pills, nothing hidden), so 360 px phones get a two-row header (STOP 2 on PR #17).
- **Copy button** ([ADR-0004](docs/adr/0004-record-model.md) part 11). Every artifact box and both contact addresses get `layouts/_partials/copy-button.html`, called with `(dict "id" <target id>)`: a `<button type="button" class="copy" hidden data-copy-target data-copy-done data-copy-failed>` plus the empty live region `<span class="copy-status" role="status" aria-live="polite">` right after it. Its text and statuses are `copy.button`, `copy.done` and `copy.failed` in `data/labels.toml`; `copy.js` only reads them. The target holds the value as text only (render rule 14): a box's id is its group key and index (`domains-0`, a hash's file name `sha256-0-0`), the footer address `contact`, the how-to-send address `contact-send`. In `artifacts.html` the button comes after the box's D10 label (`box-label.html`), so the label stays the first element after the box (render rule 4's labelled variant). `site.css` hides the button with `.copy[hidden] { display: none !important; }` (pinned by `site`, in a stylesheet every page with a button links): an author `display` overrides the browser's `[hidden]` rule, and a selector need not name `.copy` to match the button, so without that rule the button could show and do nothing without the script. Any change of `assets/js/copy.js` updates its SHA-256 in `SCRIPT_SHA256` (`tools/sitecheck.py`), and any change of `assets/css/site.css`, `assets/css/tokens.css` or `data/tokens.toml` its SHA-256 in `STYLESHEET_SHA256` (M4 PR 3 fix round 4). The script reveals a button only with the clipboard API in a secure context and copies `textContent` unchanged (defanged), never a rewritten form.
- **Search** ([ADR-0005](docs/adr/0005-search.md) parts 3 and 4). `assets/js/search.js` fetches `/feed.json` (the match keys: names, aliases, artifacts) and the form's `action`, `/a-z/` (the answers), on the first focus of `#q` or the first submit, never on load; a submit folds (NFKC, invisibles removed, dots, then NFC, fix round 1) and refangs the query (part 3, with the `DEFAULT_IGNORABLE`, `DOT_CHARS` and `DEFANGS` tables of `sitecheck.py` as numbers and short literals), reveals exactly one result section, fills its list with `document.importNode` copies of the matching `/a-z/` entries, moves focus to its heading without scrolling and scrolls the section's top to the top of the viewport at once (fix round 2: focus alone left the heading at the bottom edge of a 640 px phone and the first entry below the fold), and clears `aria-busy` on every exit of the latest submit (empty query, answer, hand-over); a stale reply changes nothing. It reads every feed value through a type-checked accessor (a missing, `null` or other-typed field gives no key, so one schema-valid record never turns the search off; a feed entry `/a-z/` does not show hands only a query that matches it exactly over to `/a-z/`), calls every method of the document and the form through its prototype (`HTMLFormElement.prototype.submit.call`, `Element.prototype.getAttribute.call`), because a form control or a named element can shadow the property, applies `SEARCH_PARTIAL_MIN` to each form the partial match tests (`f` and `r`), and builds every key and query form through `addForm`, which keeps a form only when it holds a letter or digit (Unicode L or N), so no comparison of either branch involves a form without searchable content on either side (fix rounds 3 and 4; the fixture site carries the file names `/`, `-`, `?`, `~`, U+2800, U+3000 and U+200B on `meetfix` for that class). Its test is the script's one regular expression, built from the string `[\p{L}\p{N}]`, which `literals` L7 accepts exactly, by file and value, from `LITERALS_SCRIPT_PATTERNS` (a passing set pinned in `allowlists.tsv`). It holds no copy, never writes the query into the page (D8), sets `aria-busy` on `#search-results` while it waits, and hands over to `/a-z/` (the form's own submit) on a failed fetch, a feed `version` other than 1, a feed without its two lists or an `/a-z/` page without its list. No `innerHTML`, no timers, no URL but `/feed.json` and the form's `action`. Any change of the script updates its SHA-256 in `SCRIPT_SHA256`. `site.css` hides the result box and its sections with `.search-out[hidden] { display: none !important; }` for the Copy button's reason.
- **Contact.** `params.operator` and `params.contact` in `hugo.toml` are the single source for the footer, `layouts/_partials/how-to-send.html` and the page copy (About and Privacy read them through Hugo's built-in `param` shortcode, for example `{{< param contact >}}`), always rendered as plain text (no `mailto:`, SPEC §7). Report a scam and Corrections set `channel = "report"` or `"correction"` in their front matter to get the how-to-send block; the report-form milestone replaces that one partial. Before your call sets `checklist = true` to render the checklist of `data/labels.toml` with details; Home shows its titles.

## Invariants

- **No npm (D3).** Never run `npm`, `npx` or `node` on a developer machine, not even for a quick Lighthouse run. No `package.json` or lockfile in the repo. The `[security]` and `[privacy]` keys in `hugo.toml` stay (ADR-0001 hardening keys). npm-only tools run only in CI jobs whose `GITHUB_TOKEN` has no permissions (`permissions: {}`), that see only the built site and the check scripts, never the repository source, and that do not build the deploy artifact. Today that is the job `lighthouse` in `lighthouse.yml`, running `tools/lighthouse.sh`, the only file that may name the tools ([ADR-0003](docs/adr/0003-browser-checks.md) part 2). That script refuses to run outside GitHub Actions or next to `.git` or `content/`. No workflow restores an Actions cache, and the deploy path never reads anything that job can write.
- **Neutral, artifact-based records (D6, D7, D10).** A record describes artifacts, not a verdict about a company. A company or person name is either "name abused" (used without their involvement) or "front" (listing what was checked). Labels state facts, for example "reported 3 times, evidence reviewed on 2026-11-10", never "verified scam". A recruiter persona name appears only with the label "name used by the campaign, possibly a stolen identity". Attribution only as the cited source states it.
- **Nothing live (D8).** Attacker URLs and domains are always defanged: `hxxp://` or `hxxps://`, and every dot in a hostname or IP as `[.]`, for example `hxxps://login[.]meeting[.]example/join`. This applies to records, page copy, issues, PR bodies and QA reports. In record text every dotted name is written defanged, vendor, tool, brand and file names included (`Dr[.]Web`, `Next[.]js`, `Setup[.]zip`), and the only live host is the site's own, `interviewscam.com` ([ADR-0004](docs/adr/0004-record-model.md) part 3). Prefer an undotted form where it reads naturally ("Doctor Web"). Record bodies carry no bare URLs, no Markdown links and no `<…>` autolinks; live links appear only in `params.sources[].url`, and a source host never equals, sits under or sits above a domain any record declares in `params.artifacts.domains` (R15). No malware binaries, only SHA-256 hashes linking to MalwareBazaar or VirusTotal; never download a sample to check a hash. Fixtures use only RFC 2606 reserved names (`.example`, `.test`, `.invalid`, `example.com`).
- **No third-party requests (D9).** No external scripts, stylesheets, fonts, analytics or cookies. The Content Security Policy is a meta tag right after `<meta charset>` (Pages cannot set headers), and its single source is `params.csp` in `hugo.toml`.
- **Pages stays off until M6 (#7).** On the Team plan a Pages site from this private repo is public as soon as it deploys. `deploy.yml` only builds and uploads the artifact with a read-only token; no workflow may deploy or enable Pages before M6.
- **No raw evidence or personal data** in the repo, issues or PRs: no reporter identity, unredacted screenshots or mail headers. They stay in the operator's mailbox (D5, D7). Issues carry only defanged artifacts and an evidence summary.

## Workflows

- `ci.yml`: job `check`, on every PR and every push to `main`, runs `bash tools/check.sh`.
- `deploy.yml`: job `pages-artifact`, on pushes to `main` and on PRs that change it, runs `bash tools/check.sh` and uploads `public/` as the Pages artifact. It does not deploy.
- `links-external.yml`: weekly and on manual start, runs `bash tools/check.sh --external`. Not a required check.
- `lighthouse.yml` ([ADR-0003](docs/adr/0003-browser-checks.md)): on PRs that touch the site-shaping paths (`layouts/`, `assets/`, `static/`, `data/`, `i18n/`, `archetypes/`, `content/*.md`, `hugo.toml`, `tools/`, `tests/fixtures/records/pass-fixture-site/`, the workflow itself), on every push to `main` and on manual start. Job `build` (`contents: read`) runs `bash tools/check.sh` and uploads `public/`, `public-fixtures/` and `tools/` as the artifact `built-site` (1 day). Job `lighthouse` (`needs: build`, `permissions: {}`, no checkout) downloads that artifact and runs `bash tools/lighthouse.sh`, which uploads nothing. Not a required check. The page set ([ADR-0004](docs/adr/0004-record-model.md) part 10): every page of `public/` (Home, 404, the static pages and, from milestone 5, the two section pages) except the individual record pages under `/reports/` and `/campaigns/`, plus the six fixture pages of `LH_FIXTURE_PAGES` served from `public-fixtures/` on a second loopback port: Home with both lists, `/reports/`, `/campaigns/`, the report `example-front-company` (every artifact type), the campaign `example-campaign-family` (attribution) and, from M4 PR 2, `/a-z/` with every fixture record. The fixture pages are audited by their `index.html` path, because the score gate groups reports by URL path and would otherwise merge the fixture Home with the production Home.

Every action is owned by `actions/`, pinned to a 40-hex commit SHA with the tag as a comment, and listed as an `ACTION_*` pin in `tools/pins.env`. Runners are `ubuntu-24.04`, not `ubuntu-latest` (ADR-0002 part 5). Tokens are read-only.

## Upgrading a tool

Hugo: the pinning procedure in [ADR-0001](docs/adr/0001-static-site-generator.md). A Hugo upgrade also re-reads the template-name enumeration behind `literals` T1 and T2 ([ADR-0004](docs/adr/0004-record-model.md) part 13: a named body runs only through `template`, `block` and Hugo's lookups by path), because both rules rest on the pinned Hugo's resolution rules. lychee and the Nu Html Checker image: [ADR-0002](docs/adr/0002-check-toolchain.md) parts 1 and 2, including the fallback when the pinned image digest disappears upstream. Actions: resolve the upstream tag ref (`GET /repos/actions/<name>/git/ref/tags/<tag>`), then change the `ACTION_*` pin in `tools/pins.env` and the `uses:` line together. Every pin changes only in its own PR, which runs the full check.

Upgrading Lighthouse ([ADR-0003](docs/adr/0003-browser-checks.md) part 1 and Consequences): in one PR, bump `LIGHTHOUSE_VERSION` and set `LIGHTHOUSE_BEFORE` to the pin date minus 7 days (the version must be published before it). The `lighthouse` job then fails at the digest step and prints the new digest and the resolved `name@version` list. Check that list against the expected set of packages (names and versions, not code), copy the digest into `LIGHTHOUSE_TREE_SHA256`, and push; the run must go green. Never resolve or install the tree locally (D3). A runner image whose resolver changes the tree fails the same way and is re-pinned the same way.
