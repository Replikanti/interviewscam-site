# CLAUDE.md: interviewscam

Community registry of fake job-interview scams that target developers, built as a static Hugo site for interviewscam.com. This repo, `Replikanti/interviewscam-site`, is public and holds the code; the records live in the private `Replikanti/interviewscam` (below). Both the repo and the site are public, so everything here is public content.

## Source of truth

- [docs/SPEC.md](docs/SPEC.md) is the source of truth. Anything not written there is not agreed. A scope change is a PR that edits the SPEC.
- A change to a SPEC §4 decision (D1 to D10) also adds an ADR in [docs/adr/](docs/adr/README.md). Every ADR decision states why and which alternatives lost, and every number states where it comes from and what breaks at another value. A number copied from another ADR needs its own reason.

## Two repos ([ADR-0007](docs/adr/0007-repo-split.md))

- **This repo (public):** the templates, assets, data, schemas, checks, workflows, the SPEC, the ADRs, the fixtures and the intake code. Its `content/` holds only the static pages (`content/*.md`). CI here runs every check on public runners.
- **`Replikanti/interviewscam` (private), the records repo.** From PR D of Replikanti/interviewscam#38 it holds only the records (`content/reports/`, `content/campaigns/`), the real `schema/record-policy.json`, three workflows (`ci.yml` on every PR push, `lighthouse.yml` and `links-external.yml` weekly and on dispatch, nothing on a push to `main`; the deploy workflow arrives with M6, ADR-0007 part 6) and its own `README.md` and `CLAUDE.md`, and it builds the site from this repo at a pinned commit (and deploys it from M6); until PR D it still holds the old full tree, and its Actions are disabled. Its issues hold intake triage, plans and the backlog ledger; refer to them here as `Replikanti/interviewscam#N`, because a bare `#N` points at this repo.
- **Records never enter this repo**, nor drafts, intake material or removal entries. Fixture records live only under `tests/fixtures/`. From PR B of Replikanti/interviewscam#38 the guard enforces it (the public-tree rules and the workflow hardening, ADR-0007 part 4).
- **Records mode** (PR C of Replikanti/interviewscam#38): `bash tools/check.sh --records <records checkout>` runs the pin rule, the guard, the records-repo rules and every content check on the real records, from a checkout of this repo at the pinned commit (ADR-0007 part 5; "Records mode" under Local check). The canonical set of the three private workflows is `tests/fixtures/records-repo/pass-shapes/.github/workflows/`, with the fixture pin `0123456789abcdef0123456789abcdef01234567` in every `ref:`; PR D and every pin bump copy it with the real pin, and from PR E the records-repo rules require the private workflows to be these templates byte for byte with the pin.
- **Pin bumps** (from PR D of Replikanti/interviewscam#38, when the private workflows and their `ref:` lines exist). A pin is a commit of this repo's `main` with a green `check` from the GitHub Actions app. One private PR moves every `ref:` of the private workflows, at most once a day for that day's merges, plus on demand when a records PR needs new machinery. A merge here reaches production only through a pin bump, and every private run costs metered minutes (ADR-0007 part 6).

## Local check

One entry point, and CI runs it verbatim:

```sh
bash tools/check.sh             # internal links offline
bash tools/check.sh --external  # links online, third-party sources included (the fixture build stays offline)
bash tools/selftest.sh          # the fixtures alone (check.sh runs it too)
bash tools/selftest.sh --only tokens,schema  # the named suites alone (mutation sweeps, ADR-0008 part 4)
bash <public checkout at the pin>/tools/check.sh --records <records checkout> [--external]
```

**Suite selection** ([ADR-0008](docs/adr/0008-mutation-sweeps.md) part 4, Replikanti/interviewscam#40). `selftest.sh --only SUITE[,SUITE...]` runs only the named suites; a suite is the first path segment of the rows it prints (the token after `ok   ` or `FAIL ` up to `/`, a space or `:`, 59 on 2026-11-25 with `site-preview`, `render-preview`, `records-meta`, `preview-wrap`, `preview-image` and `preview-png`, plus `selftest-only`). Each fixture case and each block of rows after the fixture loop (`selftest_blocks`) is guarded by `selftest_wants` with its suite; the three runners whose rows belong to two suites (guard-public and guard-wf, pin and pin-extra, render-intake and site-intake) print them through `selftest_rows`, which keeps only the selected suites' rows; their "runner did not finish" checks count only the selected suites' rows (`selftest_ok_count`), so a failure only the partner suite sees stays out of the selection, and the line names a selected suite (`selftest_suite`). Under `--only` the rows stream to stdout as they finish and `tee` (a background job reading a FIFO, waited for by its PID) copies them to a log, so a run stopped at a sweep's budget has already printed its finished rows; the shell writes to the FIFO write-only, so a stdout reader that closes early (`| head -n 1`) ends the run with SIGPIPE instead of a block on a full FIFO. In both modes HUP, INT, TERM and PIPE stop `tee` with SIGKILL, remove the run's temp directory and raise the signal again (`selftest_on_signal`), so a calling script such as `check.sh` still stops on Ctrl-C. After the blocks the log is checked (`selftest_selection_check`): a row of an unselected suite (`FAIL selftest-only: row outside --only`) or a selected suite with no row (`FAIL selftest-only: --only <s> ran no rows`) fails the run with exit 2; `FAIL:`, `NOT RUN` and detail lines are no rows. The html and reflow invariants hold only when `html`, or `reflow` or `reflow-search`, is selected. The last line reads `selftest (only a,b): N passed, M failed, html fixtures run: x of y, reflow fixtures run: u of v`. Usage errors exit 2 before any tool is fetched: a missing value, an empty list or name, a duplicate, a name outside `^[a-z0-9][a-z0-9-]*$` (matched against the characters written out, so no locale lets a look-alike, zero-width character or newline through), any other argument, a second `--only`. Without `--only` the run and its output are unchanged, and `wiring/selftest-no-args` requires `step_selftest` to run `selftest.sh` without arguments, so CI always runs every suite. The `selftest-only/<row>` lines prove the usage errors, one and two suites end to end, an unknown suite, and the check, the row filter and the suite fallback on synthetic output; `partner-pin`, `partner-intake` and `partner-both` run the real `selftest_blocks` under `--only pin`, `--only site-intake` and `--only pin,pin-extra` with stub runners that fail one partner row, so they hold the finished checks at their call sites; `streams-rows` stops a nested `--only tokens` run (own session) with TERM after its first row: fewer rows than its cases, no summary, exit 143, no temp file; and `signal-stops-parent` sends SIGINT to the process group of a parent script that runs a nested `--only tokens` run: the parent dies of SIGINT and never reaches its next line; `pipe-closed` runs the real `selftest_main` with 50000 stub rows, started by Python with SIGPIPE at its default action (CI starts jobs with it ignored), into a reader that closes after the first row: death by SIGPIPE within 60 s and no temp file; and `term-ignored` starts a nested `--only tokens` run with SIGTERM ignored and sends it SIGINT: it dies of SIGINT within 30 s and leaves no temp file. A mutant killed only by an unselected suite reports SURVIVED (ADR-0008 part 4).

**Records mode** ([ADR-0007](docs/adr/0007-repo-split.md) part 5, Replikanti/interviewscam#38 PR C). The private records repo's workflows check out that repo as `records/` and this repo at the pinned commit as `site/`, and run `bash site/tools/check.sh --records records`; locally, the same from a worktree of this repo at the pin (`git worktree add --detach worktrees/pin-<sha12> <pin>` in the records clone) on a records worktree. `--records DIR` and `--external` each at most once, in either order (`parse_check_args`); DIR is resolved with `cd -P` and refused when it is this checkout or lies inside it (this checkout inside DIR is the local layout and allowed). Steps, in order: `pin (green check on public main)` (`sitecheck pin --sha <HEAD>`, below; right after it `unset GH_TOKEN GITHUB_TOKEN`, so no later step holds the job token), fetch-tools, `guard (repo rules)` on this checkout unchanged, `records repo (layout, workflows)` (`sitecheck records-repo --root <this checkout> --dir DIR --sha <HEAD>`, below; when it fails, every later step that reads the records repo, assembly to links, prints `NOT RUN: the records repo step failed, ...` and is recorded `NOT RUN (records repo failed)`, and `.records-site/` and `public/` are removed, so nothing of the records repo is copied, built or checked), `records assembly` (removes `.records-site/` and `public/`, then copies the `FIXTURE_COPY` entries that exist and `content/*.md` of this checkout, the files of DIR's git listing under the record sections `content/reports/` and `content/campaigns/`, and `schema/*` of this checkout with `record-policy.json` replaced by DIR's when DIR's listing has one; a symlink or a non-regular file there fails, and so does any listed file in a record section that is not `content/<section>/<name>.md` (no dot file, no subdirectory; a Hugo content adapter `_content.gotmpl` would run template code), judged on the whole listing before the first copy), `records` on `.records-site/`, the build of `.records-site/` into `public/` (so the deploy and Lighthouse artifacts keep their path), `site` and `render` on `public/` (render with the fixture-leak check against `tests/fixtures`), reflow and the Nu Html Checker on `public/` only (CI only), lychee on `public/` (online with `--external`), and last `records cleanup (.records-site/ removed)` (`step_records_cleanup`, after every run, pass or fail: `.records-site/` holds the records repo's sources, the real `retired_slugs` among them, so no later step of the job, an artifact upload included, can find a copy; the build in `public/` stays). The machinery steps (shellcheck, worker, tokens, literals, the fixture build and its site, render and links, selftest) print `NOT RUN (records mode): machinery only, held by the pinned commit's green check`, and the last line reads `RECORDS PASS on <sha12>: every content check ran and passed`, or outside CI `RECORDS LOCAL PASS on <sha12>, HTML validation and reflow not run (CI only)`, never the public all-pass wording. A real run against the GitHub API needs a pin, a commit of `main` with a green `check`, so a PR head fails the pin step by design; the self-test runs records mode against a stub API.

Prerequisites: bash, python3 3.11 or newer, curl, sha256sum, cmp, tar, git and shellcheck. No container runtime and no browser. `tools/fetch-tools.sh` downloads Hugo, lychee and workerd into `.tools/` and verifies each against the SHA-256 in `tools/pins.env` before extracting (workerd is one gzip-compressed binary, `fetch_gz`, decompressed with Python's `gzip` in isolated mode; `load_pins` requires its four keys and exports `WORKERD_BIN`).

**HTML validation and reflow run only in CI** ([ADR-0002](docs/adr/0002-check-toolchain.md) part 1, [ADR-0003](docs/adr/0003-browser-checks.md) part 6). Locally the Nu Html Checker step and the reflow step each print a `NOT RUN` line (the reflow one also names its hidden-state cases, the Copy button hidden without its script, the search results hidden until a query (M4 PR 3) and the skip link shown on keyboard focus, M3 PR 10, and from M5b PR 3 the honeypot of the intake forms without a box), and the final line reads `LOCAL PASS, HTML validation and reflow not run (CI only)`; from M4 PR 4 the reflow line also names the hit test and paint check of the pinned regions and case (8), the search typed and submitted on Home. A local green means neither that the HTML is valid nor that the pages reflow at 320 CSS px; the SPEC §8 HTML row and the reflow part of the accessibility row come only from the `check` job in CI. In CI a missing Docker image or Google Chrome is FAIL. The reflow check never looks for a browser outside `PATH` (for example a flatpak).

Steps, in order: fetch and verify the toolchain, shellcheck `tools/*.sh` (prints `shellcheck OK`; required under `CI=true`), `sitecheck guard`, the `worker` step (below), `sitecheck records`, `sitecheck tokens`, `sitecheck literals`, the Hugo build into `public/` with `--panicOnWarning`, `sitecheck site` on `public/`, `sitecheck render` on `public/` (with the fixture-leak check and the feed rules), the fixture build into `public-fixtures/` (after classifying its inputs), `sitecheck site --preview-pixels` and `sitecheck render` on `public-fixtures/` (no fixture-leak check: every record there is a fixture), `sitecheck reflow` on both trees (CI only), the Nu Html Checker on both trees (CI only), lychee on `public/` (online with `--external`), lychee on `public-fixtures/` (always offline: fixture sources and lookups are placeholders), and the self-test. Every step runs even after a failure, and the summary lists each result.

Fixture build ([ADR-0004](docs/adr/0004-record-model.md) part 10): production `content/` has no records until milestone 5, so the record templates would meet no check before then. `step_fixture_build` in `tools/check.sh` removes `.fixture-site/` and `public-fixtures/`, classifies the inputs (`fixture_inputs`, below), copies the `FIXTURE_COPY` entries that exist (`hugo.toml`, `layouts/`, `assets/`, `data/`, `static/`, `i18n/`, `archetypes/`) and the top-level `*.md` of `FIXTURE_CONTENT` (`content/`) into `.fixture-site/`, adds `tests/fixtures/records/pass-fixture-site/content/`, and builds it with the same Hugo invocation as the production build (`hugo_build`) into `public-fixtures/`. ## Safety nets (`tools/sitecheck.py`)

Python 3.11+ standard library, one file, always run as `python3 -I` ([ADR-0002](docs/adr/0002-check-toolchain.md) parts 3 and 4). Exit 0 clean, 1 on findings, 2 on a usage or internal error. A finding never prints an artifact live: values are shown defanged. Every Default_Ignorable_Code_Point (`INVISIBLE`, ranges copied from Unicode's DerivedCoreProperties.txt) is stripped before the record checks, because browsers drop them from hosts; emoji in prose keep passing. The live-form fold `norm()` applies NFC after the strip (M4 PR 4 fix round 1), so a stripped character between a letter and its accent leaves the two to compose (fixtures `site/fail-live-artifact-composed-after-invisible`, which only that NFC catches, and `records/fail-live-form-composed-after-invisible`).

- `records`: every `content/reports/*.md` and `content/campaigns/*.md` except `_index.md` is a record with TOML front matter between `+++` lines, validated against `schema/report.schema.json` or `schema/campaign.schema.json` (the SPEC §5 model, [ADR-0004](docs/adr/0004-record-model.md)). The schemas describe structure only, with `additionalProperties: false` at every level and a `description` on every property; the only top-level keys are `date` (the publication date) and `params`, so a record cannot set `title`, `url`, `slug`, `aliases`, `draft`, `build`, `outputs`, `layout`, `type`, `cascade`, `publishDate` or `expiryDate`. Validity lives in two places, the schema and the record rules below (ADR-0004 part 2). Any other directory under `content/`, a nested file or YAML front matter fails closed. The validator implements `type`, `required`, `properties`, `additionalProperties`, `items`, `enum`, `const`, `pattern`, `minLength`, `minItems`, `minimum` (numbers only), `format: date`, annotations and `x-defang`; any other keyword is an error. `x-defang: "host"` is the only mode and marks every artifact field plus the record names and aliases (`packages[].name` and `handles[].value` included, so a dotted package name is stored `socket[.]io`); the former mode `url-only` fails closed. It scans the whole value in every reading (as written, with `[://]`, `[:]` and `[@]` read as `://`, `:` and `@` through the `DEFANGS` table that `refang()` also uses, and percent-decoded) and rejects a live scheme, a `www.` prefix, a live dotted name (dot look-alikes included) and a live dotted IPv4 anywhere, a path, query, file name or repository shorthand included: write `hxxps://get[.]meeting[.]example/GoogleMeet[.]exe` and `attacker/interview[.]task`. No host has to be found first, so no scheme spelling can hide one (ADR-0004 amendment). A `urls` value must take the form `hxxp` or `hxxps`, then `://`, `[://]` or `[:]//`, then a non-empty authority that is not a bracketed IPv6 literal, then an optional path, query or fragment (`URL_FORM`); anything else is a format finding. In every host-mode field an IPv6 literal, bracketed or bare, is a finding (an IPv6 artifact cannot be declared): candidates are bracket contents and standalone colon runs, and only one that parses with `ipaddress` counts, so `dead:beef` or `Fixture::Utils` pass, and R12 reads a URL's host only from that authority. In the other fields R12 reads the host part of every token. A bare single decimal or octal number (no dot, no `0x`, not after a scheme) is an integer IPv4 when it is the whole value or the whole first part of it (`3232235777`, `2130706433/setup`), except in `handles[].value`, where it is a numeric handle; a number inside a longer value ("Studio 54") is not a host. The live form of an artifact (`[.]`, `hxxp`, `[:]`, `[@]` refanged) must not appear in any other string or body of any record (R2). Bodies carry no bare URLs (any scheme except `hxxp`/`hxxps`, `//host`, `www.`, `mailto:`), no `hxxp(s)://` with a live host after it, no live dotted IPv4, no Markdown links, images, reference links or definitions (a definition label may span lines or hold `\]`), no `<…>` autolinks and no Hugo shortcodes (`{{<`, `{{%`: their output, for example `param` or `figure link=`, is invisible to this check), also not after entity or backslash decoding (SPEC §5). ## The intake Worker ([ADR-0006](docs/adr/0006-intake-form.md), M5b)

## Design (SPEC §7, direction C "Signal")

- **Tokens.** `data/tokens.toml` is the only place a colour value may live. `assets/css/tokens.css` is a template that turns it into custom properties (`--<table>-<key>`, `_` as `-`, for example `--color-chip-text`; lengths as rem, hairlines as px), and `layouts/baseof.html` concatenates it in front of `assets/css/site.css`, minifies and fingerprints the result as the one stylesheet. `site.css` uses `var(--…)` for every colour. `assets/favicon.svg` and the `theme-color` meta read the tokens too. Read the data through `hugo.Data`, never `.Site.Data` (deprecated; the build runs with `--panicOnWarning`).
- **Adding a colour.** Add the key with a comment on why it exists, then a `[[pair]]` for every foreground/background combination the layout places it in, with the floored ratio (`sitecheck tokens` prints the real value when the stated one is wrong). A colour that only decorates (a border the surface change already carries) gets no pair and says so in its comment.
- **Placement.** `input_border` is 3.15:1 on `card` but 2.91:1 on `ground`, so inputs and bordered buttons sit only on cards; review checks it, the check cannot. Orange (`cta`, `warn_*`) only on warnings and the call to action, never on a state chip (D6).
- **Markup.** No `style` attribute, `<style>` element, inline script or `on*` handler (the CSP blocks them; `site` rule (c)). Two pinned scripts ([ADR-0005](docs/adr/0005-search.md) part 5): `assets/js/copy.js` on every page and `assets/js/search.js` on Home only (`eq .Kind "home"`), each loaded once by `baseof.html` (minified, fingerprinted with SHA-384, `integrity`, `defer`; `site` rule (j)). Icons come from `layouts/_partials/icon.html`: inline SVG, `aria-hidden`, stroked in `currentColor`, coloured by a CSS class on the element around them. `visually-hidden` is the one utility class (the skip link) and, with the rules `.copy[hidden]` and `.search-out[hidden]`, the only place for `!important` (ADR-0003 part 6, ADR-0004 part 11, ADR-0005 part 6). The layout is fluid (`flex-wrap`, `min-width: 0`) and reflows at 320 CSS px. The only media queries compact the header below 390 px (24rem and 21.25rem: smaller wordmark, CTA and pills, nothing hidden), so 360 px phones get a two-row header (STOP 2 on PR #17).
- **Copy button** ([ADR-0004](docs/adr/0004-record-model.md) part 11). Every artifact box and both contact addresses get `layouts/_partials/copy-button.html`, called with `(dict "id" <target id>)`: a `<button type="button" class="copy" hidden data-copy-target data-copy-done data-copy-failed>` plus the empty live region `<span class="copy-status" role="status" aria-live="polite">` right after it. Its text and statuses are `copy.button`, `copy.done` and `copy.failed` in `data/labels.toml`; `copy.js` only reads them. The target holds the value as text only (render rule 14): a box's id is its group key and index (`domains-0`, a hash's file name `sha256-0-0`), the footer address `contact`, the how-to-send address `contact-send`. In `artifacts.html` the button comes after the box's D10 label (`box-label.html`), so the label stays the first element after the box (render rule 4's labelled variant). `site.css` hides the button with `.copy[hidden] { display: none !important; }` (pinned by `site`, in a stylesheet every page with a button links): an author `display` overrides the browser's `[hidden]` rule, and a selector need not name `.copy` to match the button, so without that rule the button could show and do nothing without the script. Any change of `assets/js/copy.js` updates its SHA-256 in `SCRIPT_SHA256` (`tools/sitecheck.py`), and any change of `assets/css/site.css`, `assets/css/tokens.css` or `data/tokens.toml` its SHA-256 in `STYLESHEET_SHA256` (M4 PR 3 fix round 4). The script reveals a button only with the clipboard API in a secure context and copies `textContent` unchanged (defanged), never a rewritten form.
- **Search** ([ADR-0005](docs/adr/0005-search.md) parts 3 and 4). `assets/js/search.js` fetches `/feed.json` (the match keys: names, aliases, artifacts) and the form's `action`, `/a-z/` (the answers), on the first focus of `#q` or the first submit, never on load; a submit folds (NFKC, invisibles removed, dots, then NFC, fix round 1) and refangs the query (part 3, with the `DEFAULT_IGNORABLE`, `DOT_CHARS` and `DEFANGS` tables of `sitecheck.py` as numbers and short literals), reveals exactly one result section, fills its list with `document.importNode` copies of the matching `/a-z/` entries, moves focus to its heading without scrolling and scrolls the section's top to the top of the viewport at once (fix round 2: focus alone left the heading at the bottom edge of a 640 px phone and the first entry below the fold), and clears `aria-busy` on every exit of the latest submit (empty query, answer, hand-over); a stale reply changes nothing. It reads every feed value through a type-checked accessor (a missing, `null` or other-typed field gives no key, so one schema-valid record never turns the search off; a feed entry `/a-z/` does not show hands only a query that matches it exactly over to `/a-z/`), calls every method of the document and the form through its prototype (`HTMLFormElement.prototype.submit.call`, `Element.prototype.getAttribute.call`), because a form control or a named element can shadow the property, applies `SEARCH_PARTIAL_MIN` to each form the partial match tests (`f` and `r`), and builds every key and query form through `addForm`, which keeps a form only when it holds a letter or digit (Unicode L or N), so no comparison of either branch involves a form without searchable content on either side (fix rounds 3 and 4; the fixture site carries the file names `/`, `-`, `?`, `~`, U+2800, U+3000 and U+200B on `meetfix` for that class). Its test is the script's one regular expression, built from the string `[\p{L}\p{N}]`, which `literals` L7 accepts exactly, by file and value, from `LITERALS_SCRIPT_PATTERNS` (a passing set pinned in `allowlists.tsv`). It holds no copy, never writes the query into the page (D8), sets `aria-busy` on `#search-results` while it waits, and hands over to `/a-z/` (the form's own submit) on a failed fetch, a feed `version` other than 1, a feed without its two lists or an `/a-z/` page without its list. No `innerHTML`, no timers, no URL but `/feed.json` and the form's `action`. Any change of the script updates its SHA-256 in `SCRIPT_SHA256`. `site.css` hides the result box and its sections with `.search-out[hidden] { display: none !important; }` for the Copy button's reason.
- **Contact.** `params.operator` and `params.contact` in `hugo.toml` are the single source for the footer, `layouts/_partials/how-to-send.html` and the page copy (About and Privacy read them through Hugo's built-in `param` shortcode, for example `{{< param contact >}}`), always rendered as plain text (no `mailto:`, SPEC §7). Report a scam and Corrections set `channel = "report"` or `"correction"` in their front matter to get the how-to-send block; from M5b PR 3 that partial is the intake form ([ADR-0006](docs/adr/0006-intake-form.md); render rule 18 pins it), with the address and the subject line as the way out right after its submit button, and `/not-sent/` sets `not_sent = true` to get one section per result id (`not-sent.html`). Before your call sets `checklist = true` to render the checklist of `data/labels.toml` with details; Home shows its titles.

## Invariants

- **No npm (D3).** Never run `npm`, `npx` or `node` on a developer machine, not even for a quick Lighthouse run. No `package.json` or lockfile in the repo. The `[security]` and `[privacy]` keys in `hugo.toml` stay (ADR-0001 hardening keys). npm-only tools run only in CI jobs whose `GITHUB_TOKEN` has no permissions (`permissions: {}`), that see only the built site and the check scripts, never the repository source, and that do not build the deploy artifact. Today that is the job `lighthouse` in `lighthouse.yml`, running `tools/lighthouse.sh`, the only file that may name the tools ([ADR-0003](docs/adr/0003-browser-checks.md) part 2). That script refuses to run outside GitHub Actions or next to `.git` or `content/`. No workflow restores an Actions cache, and the deploy path never reads anything that job can write.
- **Neutral, artifact-based records (D6, D7, D10).** A record describes artifacts, not a verdict about a company. A company or person name is either "name abused" (used without their involvement) or "front" (listing what was checked). Labels state facts, for example "reported 3 times, evidence reviewed on 2026-11-10", never "verified scam". A recruiter persona name appears only with the label "name used by the campaign, possibly a stolen identity". Attribution only as the cited source states it.
- **Nothing live (D8).** Attacker URLs and domains are always defanged: `hxxp://` or `hxxps://`, and every dot in a hostname or IP as `[.]`, for example `hxxps://login[.]meeting[.]example/join`. This applies to records, page copy, issues, PR bodies and QA reports. In record text every dotted name is written defanged, vendor, tool, brand and file names included (`Dr[.]Web`, `Next[.]js`, `Setup[.]zip`), and the only live host is the site's own, `interviewscam.com` ([ADR-0004](docs/adr/0004-record-model.md) part 3). Prefer an undotted form where it reads naturally ("Doctor Web"). Record bodies carry no bare URLs, no Markdown links and no `<…>` autolinks; live links appear only in `params.sources[].url`, and a source host never equals, sits under or sits above a domain any record declares in `params.artifacts.domains` (R15). No malware binaries, only SHA-256 hashes linking to MalwareBazaar or VirusTotal; never download a sample to check a hash. Fixtures use only RFC 2606 reserved names (`.example`, `.test`, `.invalid`, `example.com`).
- **No third-party requests (D9).** No external scripts, stylesheets, fonts, analytics or cookies. The Content Security Policy is a meta tag right after `<meta charset>` (Pages cannot set headers), and its single source is `params.csp` in `hugo.toml`.
- **Pages stays off until M6 (Replikanti/interviewscam#7).** Pages is published from the private records repo (D4, ADR-0007 part 1), and on the Team plan a Pages site from a private repo is public as soon as it deploys. The records repo has no deploy workflow until M6, which adds it (ADR-0007 part 6); no workflow in either repo may deploy or enable Pages before M6, and this repo has no deploy workflow and never publishes Pages (D4).
- **No Worker deploy from CI** ([ADR-0006](docs/adr/0006-intake-form.md) part 10). Only the operator deploys, from their own machine, with `tools/intake.py` and a dashboard-made token valid to the next 00:00 UTC; no workflow holds a Cloudflare token. No Cloudflare token, account ID, zone ID or destination address enters the repo; the tool prompts for them and never writes them.
- **No raw evidence or personal data** in the repo, issues or PRs: no reporter identity, unredacted screenshots or mail headers. They stay in the operator's mailbox (D5, D7). Issues carry only defanged artifacts and an evidence summary.

## Mutation sweeps ([ADR-0008](docs/adr/0008-mutation-sweeps.md))

A sweep proves a safety net by mutation: each mutant is a find and replace on a tracked file, run against the self-test suites that should kill it. Sweeps run only through `mutation-sweep.yml` on GitHub's runners; the local machine only starts a run, downloads its results and merges them. Never run `tools/mutate.py shard` or a sweep locally (the shard refuses to run outside a `workflow_dispatch` job).

Recipe (ADR-0008 part 9):

1. `git switch -c sweep/<pr>-<impl|qa>-r<round> <PR head sha>`, add `tests/mutants/<pr>-<impl|qa>-r<round>.jsonl`, scrub the staged diff, commit, push. Sweep branches are never merged; QA branches from the PR head on its own.
2. `gh workflow run mutation-sweep.yml -R Replikanti/interviewscam-site --ref <branch> -f mutants=<path>`.
3. Find the run whose `headSha` is the pushed commit (`gh run list -R Replikanti/interviewscam-site --workflow mutation-sweep.yml --branch <branch> --event workflow_dispatch --json databaseId,headSha`) and wait for it in the foreground (`gh run watch <id> --exit-status`, or poll `gh run view <id> --json status,conclusion`).
4. `gh run download <id> -R Replikanti/interviewscam-site -D <dir>`, then `python3 -I -B tools/mutate.py merge <dir>`: the merged `results.tsv` in file order on stdout; on stderr `mutate: sweep of <sha> with <mutant file> (sha256 <digest>)` and `mutate: M mutants: k killed, s survived, i invalid, t timeout; e killed by another row (expected=no); complete` (exit 0; an `expected=no` kill is still a kill, read its log), or `INCOMPLETE` (exit 1) on a missing or duplicate shard, mixed commits or mutant files, a row in the wrong shard, a duplicate or unknown id, or a mutant without a verdict.
5. Cite the run URL in the PR or QA comment, then delete the sweep branch.

The mutant file (part 3): JSON Lines, ASCII only (other characters as `\uXXXX`), LF only, a final LF, no blank line; one object per mutant with `id` (`^[a-z0-9][a-z0-9._-]{0,99}$`, unique), `suites` (distinct suite names, or exactly `["*"]` for the whole self-test), `edits` (a non-empty list of exactly `file`, `find`, `replace`; `file` a tracked regular UTF-8 file at `HEAD` in plain relative form, `find` non-empty and unlike `replace`), optional `expect` (the row names that should kill it) and `note`. Duplicate keys, `NaN`, `Infinity` and wrong types fail the whole file (exit 2 in every shard). Each edit must match exactly once, overlapping matches counted, in the text the earlier edits left, or the mutant is INVALID.

What a shard does (`tools/mutate.py`, parts 5 to 8): it takes mutant i (0-based) when (i mod 20) + 1 is its index, adds a detached worktree of `HEAD` under `$RUNNER_TEMP/mutate/tree` and removes `tests/mutants/` there in a throwaway commit of the tree's own (`drop_mutant_files`: the guard's PT2a refuses a multi-line JSON Lines file, so `records-mode`, which runs the guard on a copy of the tree, would fail on the mutant files; a mutant may not edit a file under `tests/mutants/`), runs one unmutated control per distinct suite set (sorted) in order of first appearance with the remaining deadline as its timeout, then each mutant with `bash tools/selftest.sh --only <suites>` in its own session, within the budget B = 2 × T_control + 220 s; at the budget the whole process group gets SIGKILL. After every run the runner, a child subreaper, kills and reaps every process the run left (`kill_strays`, also those in a new session or with a cleared environment), then `restore_tree` compares the git state a run can write (`git_state`: common `config`, `info/`, `hooks/`, `shallow`, alternates; the tree's `config.worktree`, `info/`, `commondir`, `gitdir` and `.git` file; replace refs; global config files; every entry of the common `objects/` with size, mtime, ctime and inode, `info/commit-graph*` and `info/packs` aside, because git does not verify a hash on read) with the snapshot taken right after that commit (`Pristine`), refuses anything under `.tools/` that is not a regular file or a directory (`tools_cache_problem`), clears skip-worktree and assume-unchanged bits, detaches HEAD at that commit, runs `git reset --hard` and `git clean -ffdx -e .tools` (every call with `core.hooksPath=/dev/null`, `core.fsmonitor=false`, no global or system config, `GIT_NO_REPLACE_OBJECTS`), and checks HEAD, `git ls-files -v` (only `H`), the status and every file of the tree byte for byte against the snapshot (`tree_content`); a stray alive after `STRAY_SWEEP_S` (10 s), a changed git state (a mutant run that commits included) or a failed check makes that mutant ERROR and the rest NOT-RUN, the reason in its log. Trust boundary (ADR-0008 part 5): the runner itself (passwordless `sudo`: `/etc/gitconfig`, binaries) is not defended; each shard runs on a fresh runner. Verdicts: KILLED (exit 1 with a `FAIL` row; the killer is the first `FAIL` row's name, `selftest` for a `FAIL:` line), SURVIVED (exit 0, no `FAIL` row), INVALID, TIMEOUT (past B, even after a `FAIL` row; never a kill). A failing control makes every mutant of the shard VOID; a mutant that cannot finish before the deadline D (`DEADLINE_S` = `JOB_TIMEOUT_MIN` × 60 − 60 s) is NOT-RUN; any other outcome is ERROR. VOID, NOT-RUN and ERROR are no verdicts, and the shard then exits 1. The artifact holds `results.tsv` (`id verdict killer expected shard seconds`; the killer escaped to printable ASCII), `meta.txt` (commit, shard, mutant file and SHA-256, one `control` line per suite set, `deadline_s`, `complete`), a copy of the mutant file and `logs/` (one log per control and mutant, `internal-error.log` after an exception); the step summary shows the same table. A mutant killed only by a suite it does not select reports SURVIVED (part 4), so every survivor is read. Self-test: the `mutate/<test>` rows run `tests/mutate/test_mutate.py` (stub repositories, a stub `selftest.sh` driven by its target file, patched budgets and an injected clock), and `mutate/unittest` fails on a failing exit, no case, a skip, an expected failure, an unexpected success or a case line that does not count.

## Upgrading a tool

Hugo: the pinning procedure in [ADR-0001](docs/adr/0001-static-site-generator.md). A Hugo upgrade also re-reads the template-name enumeration behind `literals` T1 and T2 ([ADR-0004](docs/adr/0004-record-model.md) part 13: a named body runs only through `template`, `block` and Hugo's lookups by path), because both rules rest on the pinned Hugo's resolution rules. lychee and the Nu Html Checker image: [ADR-0002](docs/adr/0002-check-toolchain.md) parts 1 and 2, including the fallback when the pinned image digest disappears upstream. Actions: resolve the upstream tag ref (`GET /repos/actions/<name>/git/ref/tags/<tag>`), then change the `ACTION_*` pin in `tools/pins.env` and the `uses:` line together. Every pin changes only in its own PR, which runs the full check.

workerd ([ADR-0006](docs/adr/0006-intake-form.md) Numbers, "workerd pin and `compatibility_date`"): in one PR, change `WORKERD_VERSION`, `WORKERD_URL` and `WORKERD_SHA256` (the SHA-256 of the release's `workerd-linux-64.gz`, checked against the asset `digest` GitHub's release API reports and against the downloaded file), and set `WORKERD_COMPAT_DATE` and every `compatibilityDate` of `tests/worker/config.capnp` to the release date; the `worker` step must pass, and the operator redeploys so production runs the same date.

Confusables (Replikanti/interviewscam#28, [ADR-0004](docs/adr/0004-record-model.md) Numbers, "Confusables data"): in one PR, download `confusables.txt` of the new version from `https://www.unicode.org/Public/<version>/security/` into `tools/unicode/`, compare it byte for byte with the member of `uts39-data-<version>.zip` from the same directory, and set `CONFUSABLES_VERSION`, `CONFUSABLES_SHA256` and `CONFUSABLES_ENTRIES` together (check `CAPITAL_L` against `confusables/capital-l-set` and `SKELETON_ROUNDS` against the measured rounds, and refresh `tools/unicode/LICENSE` and `CONFUSABLES_LICENSE_SHA256` when the licence text changed). The table is behaviour (17.0.0 to 18.0.0 added 1,216 entries and removed 1,069), so the PR runs the full check and gets the safety-net review. The bidi data moves in the same PR and to the same version: `DerivedBidiClass.txt` (from `ucd/extracted/`) and `BidiBrackets.txt` byte for byte from `https://www.unicode.org/Public/<version>/ucd/`, and `BidiCharacterTest-ltr.txt` re-derived from that version's `BidiCharacterTest.txt` as its header describes (the header up to the first `#####` line, the derivation note with the full file's SHA-256, then every data line whose field 1 is 0 and that holds no code point of class LRE, RLE, LRO, RLO, PDF, LRI, RLI, FSI or PDI, in file order); set `UNICODE_DATA_VERSION`, the `BIDI_*_SHA256`, `BIDI_CLASS_ENTRIES`, `BIDI_BRACKETS_ENTRIES`, `BIDI_TEST_ROWS` and `BIDI_TEST_SOURCE_SHA256` together, and `confusables/bidi-conformance` must stay at 0 differing lines.

Upgrading Lighthouse ([ADR-0003](docs/adr/0003-browser-checks.md) part 1 and Consequences): in one PR, bump `LIGHTHOUSE_VERSION` and set `LIGHTHOUSE_BEFORE` to the pin date minus 7 days (the version must be published before it). The `lighthouse` job then fails at the digest step and prints the new digest and the resolved `name@version` list. Check that list against the expected set of packages (names and versions, not code), copy the digest into `LIGHTHOUSE_TREE_SHA256`, and push; the run must go green. Never resolve or install the tree locally (D3). A runner image whose resolver changes the tree fails the same way and is re-pinned the same way.

## Content scrub

Before every commit, the staged diff (`git diff --cached`) must contain no client names and no paths from a developer machine (home directories, worktree paths). Envelope SDLC sessions run the scrub grep from their repo routing table. The pattern is not written here, because a file that spells out the names would itself match the scrub.
